# sash v6: tier 3 (WASM functions, provenance, atomic, record and replay)

Status: approved by Ryan 2026-11-12; every "Recommended" below is the decision. Nothing built. v6 starts after v5. Sections 3 and 4 have agent parts that belong in `systemapi.io/docs/sash-jobs-contract.md`, not in this repo. `par` and `sash lint` come from v5 (`2026-11-12-sash-language-v5.md`).

Every v1–v4 and `needs` rule holds: no PATH exec, no `&`, no `eval`, values never parsed as source, command names literal (`command_from_value`), verbs only through `machine.do` (`internal/lang/eval.go`) and the agent re-check, everything bounded by the 8 MiB value cap and depth 64 (`data.go`). Security code follows `ads-fable-utils/SECURITY-RULES.md`.

## 1. WASM functions (wazero, pure Go)

### Surface

```
wasm m = /srv/ops/fmt.wasm sha256 9f2c…e1     # statement
let y = [ m::render($x, 3) ]                  # expression call
```

The module name, the path, the hash, and the export name are all literals. A path or export from a value is refused at parse time, as `command_from_value` is.

### Loading

- Bytes come through `file.read`, the same door as `use`. Never through `os.ReadFile`: `readSource` in `cmd/sash/main.go` reads the script itself, but nothing else in a session may touch the host directly.
- The module must be at most 256 KiB (as built; the draft said 4 MiB, the transport allows 8 MiB). See Limits for the measurement behind it.
- sash computes the sha256 and compares it to the literal before compiling. A mismatch is exit 2 `wasm_hash`.
- When the tenant has `require_signed_scripts` on (jobs contract §5), modules follow it too: the agent checks `<file>.sig` before returning the bytes.
- Modules compile once per process into an in-memory cache. Nothing is cached on disk, since that would be a host write outside the grant.

### Runtime (wazero v1.12.0)

- `wazero.NewRuntimeWithConfig(ctx, wazero.NewRuntimeConfigInterpreter().WithMemoryLimitPages(256).WithCloseOnContextDone(true).WithCoreFeatures(api.CoreFeaturesV2))`. 256 pages is 16 MiB per instance.
- WASI is not instantiated and there are no `NewHostModuleBuilder` imports, so the import set is empty. Before instantiating, sash reads the compiled module's imports and refuses any import with exit 2 `wasm_import`. *Verify the method names `CompiledModule.ImportedFunctions` and `ExportedFunctions`.*
- `wazero.NewModuleConfig().WithStartFunctions()`: no start function. Without `WithSysWalltime`, `WithRandSource`, or `WithFS`, the defaults are inert (stdin returns EOF, stdout is discarded, no filesystem).
- A fresh instance per call, closed after the call. A module keeps no state between calls.

### ABI

The module exports `memory`, `sash_alloc(i32) -> i32`, and each function as `(ptr i32, len i32) -> i64`, where the result is ptr<<32 | len.

Arguments go in as one JSON array, written with the existing ordered `to json` encoder. The result is one JSON value, read with `from json`. The result is charged against the evaluation budget before it is built and must be at most 8 MiB. A result containing NaN or Inf, or one that is not UTF-8, is a type error.

### Limits

- Per call: the earlier of 1 s and the enclosing `timeout` deadline, applied with `context.WithDeadline`. wazero has no fuel metering, so this is the CPU bound; `WithCloseOnContextDone` aborts loops when the context ends.
- Calls count against `verbmax`.
- A trap, timeout, or memory-limit error is exit 2 `wasm_trap`.

- **Compile memory (as built).** wazero's interpreter allocates during compile in proportion to the module, worst for nesting. Measured in v1.12.0 on darwin, bytes allocated per module byte: nested `if` 633, `if`/`else` 600, nested `loop` 588, pushes (`i32.const` then `drop`) 246, binary ops and `local.get` 229-234, nested `block` 194-203, `br_table` 37, functions 67, `nop` and `unreachable` 1. Locals at their cap add a fixed 23 MB; params at their cap about 1 MB. A module of 3.9 MB of pushes allocated 930 MB, and a 3 MB type of 3M params 20.7 GB. So the module cap is 256 KiB: the worst case (nested ifs filling it) measured 158 MB, plus 23 MB for locals, under the 256 MB budget; `TestWasmCompileAllocBudget` checks it.
- **Types (as built).** A type may have at most 1,000 params and one result (`wasm_limits`), and at most 10,000 types. No value type may be `v128`, in a type or a local (`wasm_limits`): wazero accepts a `v128` local with SIMD off, and it takes two stack slots. SIMD is off in the runtime too. Known limit: a toolchain that emits multi-value function types (Rust 1.82+ enables multivalue for wasm32) is refused with `wasm_limits` even though the sash ABI exports, `(i32)→i32` and `(i32,i32)→i64`, return one value; build such modules with multivalue off.
- **Run-time frames (as built).** wazero v1.12.0's interpreter allows 2,000 frames (`callStackCeiling`, unexported and not configurable) and keeps every frame's params, locals, and operand stack on one `[]uint64` grown by append, so deep recursion re-copies it: about 38-46 bytes allocated per slot per frame. Measured on darwin: one function of 49,000 `i64` locals calling itself allocated 4.4 GB in 2.3 s before trapping; 1,024 locals, 78 MB in 23 ms. So sash refuses, with `wasm_limits`, a function whose params plus locals exceed 1,024, or whose params plus locals plus half its body size (each stack-growing instruction is at least 2 bytes) exceed 2,048 slots, and more than 32,768 params and locals in the module. A frame at the 2,048-slot cap recursing to the ceiling measured 192 MB allocated (about 32 MB live) in under 0.1 s; `TestWasmRunAllocBudget` checks it stays under 256 MB and traps within the deadline.
- **No `debug.SetMemoryLimit` (as built).** It was considered as a backstop during a call and not used: it is process-wide, so setting and restoring it around one call changes GC for every goroutine (the line editor, other calls, the agent transport) while the call runs, and two overlapping calls would restore each other's value; and it is a soft GC target, not a cap, so it cannot stop an allocation. The hard caps above are the defence.
- **Negative cache (as built).** Only failures that are properties of the bytes are remembered: a decode or validation error, an import, a limit, the ABI. A compile deadline and `wasm_busy` are not, so a module that ran out of time loads once a compile can finish.

### Determinism

There is no clock, randomness, filesystem, network, or threads (CoreFeaturesV2 does not include threads), and there are no imports. The same bytes and the same input give the same output. The one wasm-level nondeterminism is NaN bit patterns, and JSON already refuses NaN.

### Taint

**Decision:** may a secret go into a module? Either a secret in gives a secret out, or a secret argument is refused (`wasm_secret`). **Recommended: refuse in v6.0.** `decide` (`secret.go`) refuses branches on secrets because each branch is a probe. A module branches freely inside, and it leaks through whether it traps and through how long it runs. If v6.1 allows secrets in, the result is wrapped as `secretVal`, and a trap ends the line uncatchably, as `errSecretFault` does today.

### `needs`, `why`, lint, preview

A `wasm` statement is one `file.read` need on the path, with note `wasm`. Because a module cannot call verbs, it adds no needs, and the manifest stays complete (exit 0). This is why host imports are refused: one host import that reaches a verb would make every module opaque and every manifest that uses one incomplete. `why` reports the `file.read`; v5 lint treats a module call as pure computation.

### Supply chain

- wazero has no dependencies of its own. Today sash's `go.mod` has only yaml and toml.
- Pin the exact version, commit `go.sum`, run `govulncheck` in CI, and review the diff on every bump.
- Build with a `wasm` build tag; a build without it refuses `wasm` with exit 2 `wasm_unsupported`.
- The interpreter, not the compiler: it generates no native code (no RWX pages, which `execmem` policies block anyway). The cost is speed.

### As built

- **Build tag `sashwasm`, not `wasm`.** `wasm` is the GOARCH=wasm build constraint: `go build -tags wasm` on another architecture pulls the standard library's `_wasm.go` files in and fails. A build without `sashwasm` links no wazero code (`go tool nm` finds no `wazero` symbol and `go version -m` lists neither wazero nor `x/sys`) and refuses a `wasm` statement or call with exit 2 `wasm_unsupported`, reading nothing.
- **Supply chain.** wazero is pinned at v1.12.0. Unlike the note above, v1.11 and v1.12 require one module, `golang.org/x/sys` v0.44.0 (v1.10.1 requires none); it is from the Go project and pinned in `go.sum`. `./build.sh test` runs vet, tests, and `-race` with and without the tag, then `govulncheck` for both when it is installed (it does not install it).
- **Syntax.** `wasm m = <literal path> sha256 <64 lowercase hex>`; a name, path, or hash that is not a literal is a parse error. A call is `[ m::fn(args) ]`, the two names adjacent to `::`. Calling `sash_alloc` (any `sash_` export) is refused.
- **Loading.** The path is checked like `use` (`file.read`, the read roots), read through `machine.do` (so it counts against `verbmax`, is recorded, and gets an origin), then sized (exit 2 `wasm_too_large` past 256 KiB) and hashed (`wasm_hash`) before compiling (`wasm_compile` if it does not). Any import is refused (`wasm_import`), both by wazero's `ImportedFunctions`/`ImportedMemories` and by reading the import section's count, which covers table and global imports too. The module must export `memory` and `sash_alloc (i32) -> i32` (`wasm_abi`). The compile cache is per process, keyed by hash.
- **Before wazero sees the bytes.** sash walks the sections itself: every LEB128 is at most 10 bytes and fits 64 bits, every size is compared in `uint64` against what is left, and the index strictly increases, so the walk ends on any input (a section size of 2^64-11 is `wasm_compile`, not an index wrapped back to the start); `FuzzWasmSections` checks it. Any table whose min or max passes 10,000 entries is `wasm_limits`: wazero v1.12.0 has a memory limit but no table limit, and allocates a table's min entries (about 8 bytes each) on every instantiation, so a min of 100M cost 763 MB per call; 10,000 entries is 80 KB, past the indirect-call tables real compilers emit. Element segments need no cap, since the module cap bounds them.
- **Limits before compile.** wazero's costs, measured in v1.12.0's interpreter: about 256 bytes and 0.5 µs per function, and about 400 bytes per declared local (a 20-byte module declaring 100M locals compiled for 4m39s and allocated 43 GB). sash refuses, with `wasm_limits`: more than 10,000 functions (function and code sections), more than 1,024 locals (params included) in one function or 32,768 in the module, or a frame over 2,048 slots (see Run-time frames) (summed per run-length declaration, each step bounds-checked), any table without a declared max or with a max over 10,000 entries, and any memory without a declared max or with a max over 256 pages. A declared max lets wazero refuse `table.grow` and `memory.grow` past it (`table.grow` by 100M on a table capped at 10 returns -1); the memory max is defence in depth beside `WithMemoryLimitPages`. One compile stays near 40 MB and 50 ms.
- **One compile at a time.** At most one compile is in flight per process, counting one abandoned at its deadline; another load meanwhile is `wasm_busy` at once, not queued, and is not remembered. A module refused for any other reason (a check, a compile error, the deadline, an import, the ABI) is remembered by hash, up to 1,024 hashes, and refused again without compiling, so a loop cannot make sash compile it twice.
- **Compile deadline.** Compiling stops at 2 s (`wasm_compile`). wazero's `CompileModule` takes a context but does not check it while decoding, validating, or compiling for the interpreter, so the compile runs on its own goroutine and is abandoned at the deadline; that goroutine runs on until the compile ends (bounded by the 256 KiB module), then closes what it built, which nothing uses.
- **Calls.** A fresh anonymous instance (`WithStartFunctions()`, `WithName("")`), closed after; arguments as one compact JSON array from the ordered encoder; an export that is not `(i32, i32) -> i64` is `wasm_abi`. The result length is checked against 8 MiB before it is read, charged, then must be UTF-8 and one JSON value (`type wasm result json` covers NaN, which JSON has no form for). Any trap, timeout, memory-limit failure, or out-of-bounds result is `wasm_trap`. A call counts against `verbmax`. A secret read anywhere in the expression before the call is `wasm_secret` (not a secret fault: it is a refusal, and lint reports it as `secret-to-sink`).
- **Provenance and recording.** A call adds origin `wasm m::fn` with the module's sha256. A recording names each module's hash in the header's `modules`; replay refuses a module whose hash differs (`replay_module`).
- **Test modules** in `internal/lang/testdata/wasm` are hand-assembled by `build.py` (no `wat2wasm` was available); each `.wat` beside its `.wasm` is the same module in text form.

### Open decisions

- **Decision:** interpreter or compiler. **Recommended: interpreter**, for a smaller attack surface and no W^X conflict.
- **Decision:** JSON or a typed encoding (CBOR). **Recommended: JSON**, because the codec already exists and is ordered, and it adds no dependency.
- **Decision:** verb imports gated by the grant, or none. **Recommended: none**, because imports would break the completeness of `needs` and add a second path to verbs.
- **Decision:** a new `wasm` entitlement or not. **Recommended: not.** Loading is a `file.read` and a call is pure computation, like `sha256`. A tenant that wants control turns on signed scripts.

**Depends on:** nothing. Signing follows jobs §5 when that lands.
**Size:** human 3–4 weeks; CC 3–5 days.

## 2. Value provenance

### Model

Provenance is tracked per binding, not per datum. `value` gains `prov []uint32`, a list of IDs into a per-State origin table. An origin is: the verb key; the target (literal path, unit, key; at most 256 bytes); the script and line (a `use` file is named by its path); and the sha256 of the response bytes.

### Propagation

The lookup wrapper that marks taint (`taintLookup`, `expr.go`) also collects the `prov` of each name it reads. The result's provenance is the union of those plus any verb origins in the pipeline. Filters, `|>`, `template` (plus the template file's own `file.read` origin), and `template_file` follow the same union rule. Functions: parameters carry their argument's provenance, and a return value carries the union of what the body read. A WASM call adds an origin `wasm m::fn sha256 <module>`.

### Caps

- At most 16 origins per value. Past that, one `overflow` origin is kept and the display says "truncated".
- At most 10,000 origins per State, the same as the `checks` cap. Past that, new values get `overflow`.
- Worst case about 3.5 MiB. Provenance never fails a run.

### Display

**Decision:** `why $x` or a new builtin. **Recommended: `origin x`** (takes a name, not `$x`). `why` already takes the rest of the line as a line to explain (`line/editor.go`), so `why $x` would explain the stage `$x`. `origin` also works in scripts, returns rows (`origin`, `key`, `target`, `line`, `hash`) for `|> to json`, and prints through the `needs` cell escaping.

### Secrets

Provenance shows where a secret came from, never what it is. A secret value's rows print `hash ***`, because a hash of a low-entropy value can be guessed offline. Targets can never be secret, because a verb argument that carries a secret is already refused. `secret get` (jobs §3) shows the name, which the audit already holds.

### Logs and audit

`TODO_CODEX_OR_CLAUDE.md` says: do not log a path, a body, or a command line. So provenance never goes into the agent audit or `log`; a `log` field holding a value prints the value as today, never its lineage. A recording (§4) may carry provenance, because a recording is held to the same rules as host data.

### Open decisions

- **Decision:** per binding or per datum (row level). **Recommended: per binding**, because it hooks into the existing taint lookup. Per datum would wrap every `any`, the way `secretVal` does, and touch every function.
- **Decision:** content hash for non-secrets on display. **Recommended: yes on the terminal, never in logs.**

### As built

- A statement gathers the provenance of every name it reads (`$x`, `[ ]`, row filters) and every door call it makes; whatever it binds (`let`, `declare`, `for` names, `with`, a `catch` name) gets that union. Nested bodies fold into their statement, so a fn's return carries what its body read; parameters carry their argument word's provenance. Top-level statements fold into nothing.
- An origin is recorded when a door call answers: the key, the target (the verb's path, or the unit, package, or sysctl name; capped at 256 bytes, escaped; `***` if the stage read a secret), the source (`script`, or a `use` file's path) and line, and the sha256 of the response (the bytes, or for rows each column and cell length-prefixed, streamed). A fn body's lines are the text that defined it.
- `origin name` returns rows `origin, key, target, line, hash`; an unknown name is exit 2 `unset name`; `origin $x` is `usage origin name`; a value with no origins has no rows. Cells are escaped once when built and not again on display.
- Secrets are hidden per origin, not per binding: hiding only when the queried value is itself secret leaked the hash of a secret's source through `origin raw` (late-bound `declare -s tok = $raw`), through a value computed from `raw`, and through a second read of the same file. Whenever a secret is bound (`declare -s`, or any binding of a secret value, at any time), every origin in its provenance is marked secret, its response hash joins a set of secret hashes, and its texts join a set of secret texts; all three only grow. `origin` prints `hash ***` for a marked origin, for any origin whose response hash is a secret hash, and for any origin whose response held a secret text bound when it arrived (four runes or more anywhere in a field, shorter ones as a whole field, as the recording's rule).
- A secret's own provenance is capped at 16 origins, so binding one also marks the full provenance of every name its binding statement read. When the secret's provenance or any of those names' provenance overflowed, the lost origins cannot be named, and every origin recorded so far is marked secret: over-hiding, never a leak.
- `origin` output is for the same audience as values. A non-secret value's response hash is shown because the value itself is visible to whoever can run `origin`; only secrets, and what they came from, are hidden.
- What this cannot catch: response bytes are not kept (up to 8 MiB each, 10,000 origins), so a response that arrived before an unrelated secret was bound, shares no lineage with it, and is not byte-identical to its source, is not re-checked against that secret's text. The hash shown for such a response is of the whole response, so guessing the secret from it needs the rest of the response too.
- Caps: past 16, a value keeps 15 origins and an `overflow` row (`truncated`); past 10,000 a State gives out `overflow`. Neither fails a run.
- Recordings do not carry provenance: replay derives it from the same responses (a redacted response hashes as its `***`).
- Cost: `BenchmarkBindings10k` (10,000 bindings, 2,500 verb calls) measured 31.8 ms without and 35.6 ms with (+12%).

**Depends on:** nothing. It uses §1's origin kind if §1 lands first.
**Size:** human 2 weeks; CC 2–3 days.

## 3. `atomic { }` rollback

### What it means

```
atomic {
  template_file app.yaml app.tpl /srv/app/app.conf
  "x" > /srv/app/flag
  check "conf" [ … ]
}
```

The `file.write`s inside the block either all stay or are all restored. A failed `check` (even without `set -e`), a non-zero status, an uncaught error, `timeout`, or a cap rolls the block back.

### Refused inside `atomic` (sash; exit 2 `atomic_irreversible`)

- `unit.restart`, `package.install`, `sysctl.set`.
- `use`, nested `atomic`, `retry` around a refused verb, and `par` (v5).

The check is static, before the block starts: command names are literal, so the `needs` walker (`needsEachPipe`) finds every stage, including the bodies of called functions. It is checked again in `machine.do` as a backstop for `unit $op`.

**Decision:** allow `sysctl.set` with the old value captured. **Recommended: not in v6.0.** The kernel acts on the value the moment it is set, so a restore puts the number back but does not undo its effects. `unit.restart` cannot be undone at all.

### Split of the work

| Part | Owner |
| --- | --- |
| Syntax, static refusal, plan mode (`plan: would begin atomic`, no agent call), rollback triggers, sending `atomic.begin` / `atomic.commit` / `atomic.abort` through `machine.do`, exit codes | sash |
| New keys `atomic.*` in `sashDispatchAt` (today they fall to `default: denied`) | agent contract |
| Snapshot before each `file.write` inside a transaction: the file helper, running as the session identity, reads the current bytes, mode, and owner into an agent-private journal (root, 0700 dir, 0600 files). The journal entry is fsynced before `write_open`. The snapshot is never returned to sash, so a write-only root does not become readable. | agent contract |
| Restore: rewrite with the original mode, or unlink a file that did not exist. Needs a helper `unlink` op, which does not exist today. | agent contract |
| Restore is compare-and-swap: only if the file still hashes to what the transaction wrote. Otherwise leave it, mark the transaction `inconsistent`, and audit it. | agent contract |
| Cleanup: on commit, delete the snapshots. | agent contract |

### Mode dependency (jobs contract §2)

`sashFileWriteDefault` (`sash_file_linux.go`) writes with the helper's default mode today, so a restore through it would loosen a 0600 file. `atomic` therefore waits for `file.write` with a mode. A file whose current mode is outside the restorable set (0600/0640/0644, or a wider list §2 adds) is refused before the first write (`atomic_mode`).

### Crash and timeout

- **sash exits or is killed mid-block:** the agent restores when it reaps the session's one process.
- **Lease expiry:** `sashLeaseLive` already denies the next verb; the agent also restores at expiry, without waiting for a call.
- **Transaction deadline:** default 10 minutes, at most the remaining lease. The agent restores when it passes.
- **Agent crash:** on start, the agent restores every journal with no commit mark, before it accepts sessions, and audits each one.
- **Write-ahead order:** snapshot and fsync, then journal entry and fsync, then write.

### Size and audit

One open transaction per session; at most 64 files and 32 MiB of snapshots per transaction. Audit rows: begin, commit, abort, restore, inconsistent, each with the lease, actor, and file count. No paths.

### Open decisions

- **Decision:** agent journal or sash-side copies. **Recommended: agent journal.** A sash-side copy would need `file.read` on write-only roots, and it would die with the session.
- **Decision:** on a compare-and-swap conflict, overwrite or leave the file. **Recommended: leave and report.** Overwriting clobbers another writer's change.

**Depends on:** jobs contract §2 (mode), a new helper `unlink` op, and an agent reap hook.
**Size:** sash: human 1 week, CC 1–2 days. Agent: human 2–3 weeks, CC 4–5 days.

## 4. Record and replay

### Recording

A `recordParent` wraps `parent.Parent` underneath `machine.do`, after the plan check, so plan-mode stops are recorded as `plan` events and not as calls. Each event is one JSON line: `{seq, line, kind, req, resp, prev}`, where `req` is the key, argv, path, and a body hash; `resp` is the result shape and bytes or rows, capped by `proto.MaxFrame`; and `prev` is the sha256 of the previous event. The header is `{v:"sash-rec/1", script_sha256, sash_version, modules:{name:sha256}}`.

### Redaction

- When `m.sawSecret` is set for a stage, or a request body is tainted, the event stores `"***"` and the length, never a hash.
- A `secret get` response records the name and `***`.
- A `file.write` with a `mode` (a `template_file` render that read a secret, jobs §2) is recorded as tainted: `argv:["***"]`, lengths, and the `mode`, never a body hash. Replay matches on the mode, redacted or not.
- On replay, a secret is a fixed placeholder `secretVal`. Control flow stays faithful because a secret decides nothing.
- What a placeholder can change is whether an evaluation errors (for example `int($s)`), so the recording stores secret faults as events and replay checks they happen in the same places.

### Nondeterminism and how replay pins it

| Source | Pin |
| --- | --- |
| `nowFn` (deadlines, `timeout`), `log` timestamps | Each reading is recorded and replayed in order. The seam already exists (`eval.go`, `nowFn`/`sleepFn`). |
| `sleepFn` (`retry` delay) | The duration is recorded. Replay does not sleep. |
| `uuid()` (crypto/rand) | The value is recorded and fed back in replay only. Recording still uses crypto/rand. |
| WASM | Deterministic by construction. The module hash must match the header. |
| `par` (v5) | Each branch records its own event stream, tagged with the branch index; the merged order is recorded. Replay matches per branch and checks the merged order, so a scheduling difference never diverges, but a different request does. |

### Replay

`sash --replay rec.jsonl script` runs offline with the replay parent and no session. Each request must match the next event: key, argv, path, and body hash (tainted bodies match on length). The first mismatch is exit 2 `replay_diverged` with the sequence number. A recording only drives a fake parent: it never authorizes anything, and replay never reaches a host.

### Where recordings live

- **In a session:** sash must not write host files directly, so a recording goes through `file.write`, under the grant, with mode 0600 (jobs §2). A file larger than 8 MiB is split into numbered segments, each header chaining to the previous segment.
- **Jobs:** the agent's job-log store, under its retention and readers.
- **Offline:** recording against a local fake parent writes locally.

### Hash chain

The chain proves a recording is internally consistent. It does not prove who made it: anyone can recompute it, and sash holds no key.

**Decision:** audit-grade recordings, or test and debug only. **Recommended: test and debug in v6.** Audit grade needs the agent to countersign the chain head without logging guessable hashes of command lines, which is a separate agent contract.

### Privacy and retention

Recordings hold host data (file bodies, `ps` command lines). Recording is off by default and turned on with `set -o record <path>`; the path is literal and is a `file.write` need that `needs` reports. sash cannot delete files, so retention is the job store's (jobs §1) or the operator's. The header carries `expires`, and `--replay` refuses an expired recording.

### As built (offline, step 1)

- `sash --record out.jsonl --fixture fixture.json [--expires D] [-c script | file]` runs against a fixture: strict JSON naming a grant (no `*`, clean absolute roots, never `/`) and canned results, served by a fake parent. It writes a new file only (`O_EXCL`, 0600); `--expires` is 1m to 365 days, default 7 days. A fixture is the simplest safe source: it reaches no host, and the only file written is the recording.
- `sash --replay rec.jsonl --fixture fixture.json [-c script | file]` takes the fixture's grant only; every result comes from the recording and its parent refuses every call. The header is checked first (format, `script_sha256`, `expires`), then every `prev`; a broken link is exit 2 `replay_bad_chain <seq>`, another script `replay_other_script`, an expired one `replay_expired`. A request that differs (key, argv, path, body hash, redaction lengths, or event kind), a missing event, or an event the run never asks for is exit 2 `replay_diverged <seq>`.
- Events are `call`, `plan`, `now`, `sleep`, `uuid`, and `fault`; a reading's value is in `resp.value`. Glob listing during expansion goes through the tape too.
- Nothing is written until the run ends. Every event is held in memory (unredacted) and, at Finish, redacted against every secret text the run bound at any point (a set that only grows: a secret later reassigned is still redacted), then chained and written in one write. The CLI writes it to a new temp file in the same directory (`O_EXCL`, 0600), fsyncs it, hard-links it to the final name (refused if that exists), and removes the temp; a kill leaves at most a temp file, never a truncated recording at the final path. So the response that produced a secret (`declare -s tok = (cat /srv/token)`, or `let raw = (cat …)` then `declare -s tok = $raw`) is redacted even though it came first. A run killed before Finish writes nothing: a partial recording is lost, by design (safety over completeness).
- Redaction: a request whose stage read a secret (`sawSecret`), or that runs in a `declare -s` value pipe, or whose argv, path, or body contains any secret text, stores `argv:["***"]` and lengths; a response that is tainted that way or contains any secret text stores `redacted` and a length. The secret texts are each bound secret's whole text and every leaf value inside it; map keys are structure and are not secret texts. A text of four runes or more is redacted wherever it appears inside a field; a shorter one only when a whole field equals it (ignoring one trailing newline). The cost: a short secret is still caught when a field is exactly it, not when it appears inside other text; matching it everywhere (`ok`, `1`) would redact most of a recording, and a secret that short is guessable anyway. Four keeps a four-digit PIN or a short word caught inside text. Replay answers a redacted response with `***`.
- Replay compares a redacted request only on what the recording kept: the key, the event kind, and the argv, path, and body lengths. The recorder redacts against secrets bound later in the run, which replay does not know yet when it reaches that event; an exact comparison would diverge. A redacted event still has to match the key, kind, and every length, so a different verb or size diverges. An unredacted event must match exactly.
- What redaction cannot catch: host data that holds an encoding of a secret (its base64, hex, URL-encoding, or any transform) rather than its text; the length fields, which tell how long a redacted request or response was; and a secret shorter than four runes that appears inside a longer field, which stays in clear (only a whole-field match is redacted, see above).
- Size caps: 64 MiB and one million events per recording, at record time (the buffer; `record_too_large` stops the run and writes nothing) and at replay load (`replay_too_large`), with each event also under the 8 MiB frame cap. 64 MiB is eight full frames, far past a test or debug run, and bounds the memory the buffer can take.
- Line numbers come from statement offsets. `uuid()` inside `template` and `template_file` goes through the same seam, so a template's output replays identically.
- `set -o record` (and `shopt -s record`) is exit 2 `record needs file.write mode` until jobs §2.

### Open decisions

- **Decision:** record in sash or in the agent. **Recommended: sash**, because only sash sees the clock, uuid, and plan events. The agent may later countersign.
- **Decision:** JSON Lines or a binary format. **Recommended: JSON Lines**, diffable and reusing the proto JSON shapes.

**Depends on:** offline recording on nothing; in-session recording on jobs §2 (0600 mode).
**Size:** human 1.5 weeks; CC 2–3 days.

## Threats

- **Sandbox escape (WASM):** no imports (no WASI, no host functions; anything that imports is refused before instantiation); interpreter only, so no generated native code; wazero pinned and reviewed; a module is bytes pinned by hash and read under the grant; nothing a module computes is ever parsed as sash source or used as a command name.
- **Resource exhaustion:** wazero has no fuel, so the CPU bound is the deadline plus `WithCloseOnContextDone`; a memory page cap, a module size cap, calls charged against `verbmax`, results charged against the evaluation budget; provenance caps of 16 per value and 10,000 per State; atomic caps of 64 files and 32 MiB, one transaction per session; recordings split into 8 MiB segments.
- **Provenance leaking secrets:** a secret's rows show `***` for the hash, and targets can never be secret; provenance never goes into the audit or logs; secrets are refused into WASM, since run time and traps are a side channel.
- **A partial rollback that leaves the host inconsistent:** write-ahead journal fsynced before each write, restore when the agent starts; restore by compare-and-swap, reported as `inconsistent` and audited, never silent; irreversible verbs refused statically and again at the door; no restore loosens a mode, because atomic waits for jobs §2; snapshots are never returned to sash.
- **Recordings as an exfiltration path:** off by default, and a literal `file.write` need that `needs` shows; written only under file_write roots at mode 0600, through the agent; secrets stored as `***` with no hash; an expiry field; never a grant. A recording copies only data the actor could already read, but concentrates it in one file. That residual risk is accepted and documented.
- **A patched sash:** none of this weakens the agent. The agent re-checks every verb, `atomic.*` journals are agent state, and a patched sash that skips `atomic.begin` loses rollback, not policy.

## Order

1. Record and replay, offline. It gives every later section fixture-based tests, using the clock seams that already exist.
2. Provenance, sash only.
3. WASM functions, behind a build tag, with secrets refused.
4. Jobs contract §2 (`file.write` with a mode) in systemapi.io. Approved separately; already first in that contract's order.
5. Recording in sessions and jobs (needs 4).
6. Atomic, agent contract: `atomic.*` keys, the journal, the helper `unlink` op, the reap and expiry hooks, negative tests (crash mid-block, compare-and-swap conflict, mode outside the set, a file over the caps, a lease that expires before commit).
7. Atomic, sash side (needs 6).
8. Later: secrets into WASM (v6.1), and audit-grade countersigned recordings (its own agent contract).
